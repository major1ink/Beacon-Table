# Beacon Table

**Гибридный self-hosted VTT (виртуальный игровой стол) для D&D и других настольных RPG**

## Что это

DM-инструмент для стола, который работает в двух режимах одновременно (не
взаимоисключающих — можно и то, и другое сразу на одной комнате):

- **Локально** — DM управляет сценой со своего устройства, ТВ/проектор в комнате
  показывает то же самое по локальной сети, без авторизации.
- **Через интернет** — DM расшаривает адрес своего self-hosted сервера, удалённые игроки заходят по логину/паролю, заводят
  персонажей, двигают токены и кидают кубы.

## Возможности

- Гибрид локал/интернет в одной комнате одновременно
- Динамическое освещение, line-of-sight от токенов (частично реализовано)
- Видео-фоны карт и анимированные токены (mp4/webm)
- Броски кубов
- Амбиент сцены + плейлисты ДМ
- Вики-заметки ДМ с папками (настоящее дерево каталогов в `data/notes`) и
  ссылками между ними — `[[Заголовок]]` ищет в своей папке, `[[Глава 1/Таверна]]`
  адресует путём; бестиарий (личные монстры/NPC), библиотека заклинаний
- Журнал стола (`data/journal`, тоже настоящие `.md`): пишут и ДМ, и игроки.
  На каждую запись автор сам выставляет уровень для
  всего стола («нет доступа» / «только название» / «чтение» / «чтение и
  правка») и точечно для конкретных игроков; ДМ видит и правит журнал
  целиком. Общий журнал — те же записи с уровнем «чтение» по умолчанию:
  кнопка «В общий» кладёт заметку сразу всему столу, кнопка «Показать»
  открывает её у всех игроков разом. Запись журнала, как и заметку ДМ, можно
  повесить значком на карту — двойной клик по свитку её открывает
- Состояния (ослепление/испуг/истощение…): быстрая палитра ДМ, значки на
  токенах, отсчёт длительности по раундам, свой конструктор состояний
- Состояния и надетая экипировка меняют числа: КД, скорость,
  характеристики, максимум хитов, а «горит»/«регенерация» сами снимают или
  возвращают хиты в начале хода — с броском в общий лог
- Каталог "из коробки" на SRD 5.1/5.2 (CC-BY-4.0)
- Аккаунты и персонажи
- Импорт персонажей с сайта LSS
- Импорт предметов и заклинаний с ttg.club
- Импорт из Foundry VTT: как отдельного файла экспорта, так и целого
  модуля/системы по ссылке на манифест — см. ниже

## Быстрый старт

### Готовый исполняемый файл

Скачайте файл под вашу ОС/архитектуру со страницы
[Releases](https://github.com/major1ink/Beacon-Table/releases/latest) —
имя вида `beacon-table_<версия>_<ос>_<архитектура>` (`.exe` для Windows),
например `beacon-table_v0.1.0_linux_amd64`. Это готовый к запуску
исполняемый файл без установки.

```bash
chmod +x beacon-table_*        # Linux/macOS: GitHub не хранит бит "исполняемый"
./beacon-table_v0.1.0_linux_amd64
```
```powershell
.\beacon-table_v0.1.0_windows_amd64.exe
```

Перед первым запуском необходимо создать новую пустую папку. В нее поместить скаченный исполняемый файл.
При первом запуске рядом с исполняемым файлом создаются
папки `data/` (БД, аккаунты, ДМ-заметки) и `uploads/` (карты, токены). Далее после запуска необходимо перейти по адресу напечатнному в консоли.

Например:

- Окно ДМ или игрока: http://localhost:8080/
- Телевизор, проектор или любой другой экран для просмотра и трансляции:
  http://localhost:8080/broadcast.html

Экран трансляции работает без логина и пароля, поэтому вместо аккаунта у
него ключ. Получить его можно двумя способами — оба ведут к одному и тому же
доступу, который экран запоминает и дальше включается сам:

**Подтверждение с пульта** — то, что нужно телевизору. Откройте на нём
`/broadcast.html`, экран покажет четыре знака и будет ждать. У ДМ на столе в
разделе **«Настройки»** появится эта заявка (а на иконке раздела — красная
точка): сверьте код с тем, что горит на экране, и нажмите **«Пустить»** —
ключ доедет до экрана сам. Ничего вводить на телевизоре не нужно.

**Ссылка с ключом** — короткий путь, когда есть чем её открыть: телефон,
ноутбук, второе окно. Кнопка «Копировать» рядом с полем «Ссылка на
трансляцию» в тех же «Настройках».

### Настройка

Программа запускается с дефолтными настройками, в случае если нужно что-то изменить, инструкция ниже.

При первом запуске рядом с программой появляется **`beacon.conf`** — файл с
настройками, где всё закомментировано и подписано. Уберите `#` в нужной
строке, сохраните, перезапустите. Когда в новой версии появляются настройки,
они дописываются в конец файла при первом же запуске — ваши правки при этом
не трогаются:

```ini
BEACON_ADDR=:8080              # адрес и порт
BEACON_DATA_DIR=data           # база, журнал, сцены, заметки
BEACON_UPLOADS_DIR=uploads     # карты, токены, аудио
BEACON_BEHIND_PROXY=false      # сервер стоит за HTTPS-прокси
BEACON_ALLOWED_ORIGINS=        # доп. адреса, с которых можно открывать стол
```

Часть настроек правится прямо на столе ДМ — раздел **«Настройки»**, блок
«Настройки сервера». Там же видно, откуда взято текущее значение: пути и
порт показаны, но менять их можно только в файле, а настройка, заданная
переменной окружения или флагом, помечается — файл её всё равно не пересилит.
Уровень журнала и квоты применяются сразу, остальному нужен перезапуск, и
форма об этом пишет.

То же самое можно задать переменными окружения (те же имена) или флагами:

```bash
./beacon-table --addr 127.0.0.1:8080 --data /var/lib/beacon/data --behind-proxy
```

Если настройка задана в нескольких местах, побеждает более конкретное:
**флаг → переменная окружения → файл → значение по умолчанию**. Полный
список — `./beacon-table --help`.

`BEACON_BEHIND_PROXY` включайте, **только если снаружи действительно
https**: он помечает cookie флагом `Secure`, и по обычному http они
перестанут работать — войти будет нельзя. Зато за прокси без него токен
сессии уходит открытым текстом при первом же заходе по `http://`.

Он же запрещает подключаться к столу клиентам, которые не представились
адресом страницы (браузер такой заголовок присылает всегда, а скрипт или
curl — нет) и не даёт импорту модулей Foundry ходить в приватную сеть и на
localhost по ссылке от ДМ. Без `--behind-proxy` импорт
может тянуть модуль и с соседней машины в локальной сети.

`BEACON_ALLOWED_ORIGINS` в обычной установке не нужен: сервер узнаёт свой
адрес из самого запроса и принимает подключения только со страниц, открытых
по нему же. Понадобится, если обратный прокси не передаёт исходный `Host`
(nginx без `proxy_set_header Host $host`) — тогда стол не открывается, а в
журнале видно «отклонён WS-хендшейк». Правильнее починить прокси, но список
разрешённых адресов даёт выход, если это почему-то невозможно.

### Запуск в Docker

```bash
docker compose up -d
```

Настройки — через `environment` в `docker-compose.yml` или через тот же
`beacon.conf`: раскомментируйте в нём `env_file`. Данные лежат на томах
`beacon-data` и `beacon-uploads`, так что пересоздание контейнера их не
трогает.

### Запуск службой на сервере

В [`deploy/beacon-table.service`](deploy/beacon-table.service) — готовый
юнит systemd; порядок установки описан комментарием в самом файле.
Настройки он берёт из `/etc/beacon-table/beacon.conf` — того же файла, что
приложение создаёт рядом с собой.

### HTTPS

Своего TLS у сервера нет — его даёт обратный прокси.
[`deploy/Caddyfile.example`](deploy/Caddyfile.example) — готовый конфиг для
[Caddy](https://caddyserver.com): он сам получает сертификат Let's Encrypt и
продлевает его, нужен только домен на этот сервер и открытые порты 80/443.
Вместе с прокси поставьте в `beacon.conf`:

```ini
BEACON_ADDR=127.0.0.1:8080
BEACON_BEHIND_PROXY=true
```

В `docker-compose.yml` для Caddy есть закомментированный сервис.

### Место под загрузками

По умолчанию не ограничено. Если сервер живёт на VPS с небольшим диском,
задайте квоту — общую и/или на каждый мир:

```ini
BEACON_UPLOADS_QUOTA=20GB        # на весь сервер
BEACON_UPLOADS_WORLD_QUOTA=5GB   # на каждый мир по отдельности
```

Загрузка сверх квоты отклоняется с сообщением, в котором видно, сколько
занято и сколько отведено; ничего не удаляется само. Сколько осталось,
видно в разделе **«Ассеты»** на столе ДМ — строкой над сеткой файлов.
Импорт мира из архива отказывается ещё до распаковки, если содержимое не
влезет.

Квота считает только каталог загрузок. Резервные копии живут отдельно и
ограничены своим `BEACON_BACKUP_KEEP`.

### Журнал и проверка живости

`GET /healthz` отвечает `200`, если сервер работает и база откликается, и
`503`, если нет — это точка для мониторинга, `systemctl` и docker
healthcheck (в образе он уже настроен). Авторизация не нужна, ничего кроме
статуса и версии ручка не сообщает.

Подробность журнала — `BEACON_LOG_LEVEL` (`debug`, `info`, `warn`, `error`)
и формат `BEACON_LOG_FORMAT` (`text` или `json`):

```ini
BEACON_LOG_LEVEL=info
BEACON_LOG_FORMAT=text
```

На `info` в журнал идут события (запуск, смена мира, бэкапы), на `warn` —
только неудачные входы, отклонённые подключения и повреждённые данные. На
`debug` добавляется строка на каждый запрос к API — удобно при разборе
проблемы, но журнал растёт быстро. Статика и загруженные файлы не
логируются никогда: одна открытая карта даёт десятки запросов.

### Резервное копирование

Включено по умолчанию. Раз в сутки (и один раз при старте) приложение делает
снимок базы через `VACUUM INTO` — копировать файл SQLite на живой системе
нельзя, вышел бы битый снимок — и кладёт его вместе с каталогами данных и
загрузок в один архив `data/backups/beacon-backup-*.tar.gz`. Каждый архив
тут же проверяется на восстановимость: если снимок не открывается, архив не
сохраняется. Хранятся последние 7 штук.

Настройки — в `beacon.conf`:

```ini
BEACON_BACKUP_ENABLED=true      # выключить: false
BEACON_BACKUP_DIR=data/backups  # лучше на отдельный диск/том
BEACON_BACKUP_INTERVAL=24h
BEACON_BACKUP_KEEP=7
```

Разовый бэкап прямо сейчас: `./beacon-table backup`.

**Восстановление:** остановите сервер, распакуйте архив на место каталогов
данных и загрузок (`tar xzf beacon-backup-….tar.gz` в корне рабочей папки),
запустите снова. Временный пароль `dm` при этом выпустится заново — смотрите
его в журнале запуска.

### Защита входа от подбора

Пять неудачных попыток входа подряд с одного адреса или под одним логином
закрывают этот адрес/логин на минуту, дальше пауза растёт. Успешный вход
счётчик обнуляет. Отдельно ограничена и саморегистрация. Всё это в памяти —
перезапуск сервера счётчики сбрасывает.

Если при обычном входе прилетает «слишком много попыток входа» — значит
кто-то (или вы сами) недавно ошибался паролем к этому логину; подождите
минуту. Заблокировать так `dm` навсегда нельзя — доступ возвращается сам,
как только пауза истечёт.

### Первый запуск на Windows: предупреждение SmartScreen

При запуске скачанного `.exe` Windows покажет окно **«Система Windows защитила
ваш компьютер»** с пометкой «Издатель: Неизвестный издатель».

Это не вирус и не сбой сборки: релизные бинарники пока не подписаны
сертификатом code signing, а SmartScreen блокирует любой исполняемый файл без
подписи и накопленной репутации. Подпись релизов в планах.

Чтобы запустить:

1. Нажмите **«Подробнее»** в окне предупреждения.
2. Нажмите **«Выполнить в любом случае»**.

Если кнопки «Подробнее» нет, снимите с файла метку «скачано из интернета»
(Mark-of-the-Web) и запустите снова:

```powershell
Unblock-File .\beacon-table_v0.1.0_windows_amd64.exe
```

То же самое через свойства файла: правый клик → **Свойства** → внизу вкладки
«Общие» галочка **«Разблокировать»** → OK.

Антивирус может дополнительно поместить файл в карантин — в этом случае
добавьте папку с Beacon Table в исключения.

## Импорт компендиумов из Foundry VTT

Панель **«Справочник»** на столе ДМ → **«＋ Импорт из Foundry VTT»**. Вставьте
ссылку на манифест модуля или системы (файл `module.json` / `system.json` —
её дают на странице модуля), нажмите «Проверить»: сервер скачает архив этой
версии, распакует его и покажет список компендиумов с количеством записей по
разделам. Дальше отмечаете, что переносить, и жмёте «Импортировать
выбранное».

Что куда едет:

| В модуле Foundry | В Beacon Table |
| --- | --- |
| Item: оружие/снаряжение/расходники | Библиотека предметов |
| Item: заклинания | Библиотека заклинаний |
| Item: классы, архетипы, виды, предыстории, черты | Справочник |
| Item: эффекты (ActiveEffect) | Библиотека состояний |
| Actor: NPC и персонажи | Бестиарий |
| JournalEntry | Заметки ДМ **или** журнал стола — галочка «журналы → в журнал стола» в диалоге импорта; и там, и там раскладываются по папкам `<модуль>/<компендиум>/<папки модуля>`. В журнал записи ложатся закрытыми (доступ «нет» по умолчанию): что открыть игрокам, решает ДМ |
| Scene | Сцены стола: фон, сетка, стены, двери, источники света, токены |
| Playlist | Плейлисты ДМ |
| Adventure | Разбирается на всё перечисленное выше |
| RollTable, Macro, Cards | Не переносятся |

Картинки, карты и звуковые дорожки, которые лежат в самом архиве, попадают в
библиотеку загрузок (`uploads/…/foundry/<id модуля>`), и карточки ссылаются
уже на них — включая картинки, вставленные прямо в текст журнала, и
страницы-иллюстрации целиком. Если путь в документе не сошёлся с архивом
буква в букву (другой регистр, файл переехал при сборке релиза), файл ищется
по имени. Ссылки на ассеты **самого** Foundry (`icons/magic/…` и подобные) и
на арт, который модуль не распространяет, перенести неоткуда: такие карточки
приезжают без картинки, а в заметке на месте иллюстрации остаётся строка
«иллюстрация не перенесена — в архиве модуля нет файла …». Общее количество
ненайденных файлов видно в отчёте импорта.

**Ссылки внутри текстов.** В Foundry перекрёстная ссылка выглядит как
`@UUID[Compendium.модуль.пак.JournalEntry.abc123]{Правила перемещения}` (или
`@Embed[…]` для вставки чужого текста). Импорт переводит их в ссылки Beacon
Table на те же документы этого модуля — клик по такой ссылке в заметке или в
описании карточки открывает цель плавающим окном. Ссылка на то, что перенести
некуда (таблица случайностей, макрос) или что лежит в другом модуле,
превращается в обычный текст подписи — макросов Foundry в тексте не остаётся.
`@Embed` вставкой не становится: вместо чужого текста целиком остаётся ссылка
на него. Ссылка на отдельную страницу журнала открывает заметку сразу на
нужном разделе — страницы у нас становятся разделами одной заметки.

**Броски внутри текстов.** Инлайн-броски Foundry тоже переводятся:
`[[/r 2d6 + 3]]` становится обычной формулой в тексте — а формулу приложение
делает кликабельной само (клик кидает кубик в общий лог стола, как в
статблоках), — а `[[/save dex 15]]` / `[[/check ste 12]]` превращаются во
фразу «спасбросок: Лов (СЛ 15)» / «проверка: Скрытность (СЛ 12)». Если текст
модуля и так пишет следом «saving throw», слово не дублируется.

Поддерживаются все три формата паков: LevelDB (Foundry v11 и новее), NeDB
`.db` (v10 и раньше) и каталоги с `.json`. Скачанный архив держится в кэше
(`data/…/foundry-cache`) два часа, чтобы импорт нескольких паков подряд не
качал его заново.

**Повторный импорт.** Всё, что импортируется, сверяется с тем, что уже есть.
Карточки (предметы, заклинания, существа, справочник) ищутся по названию,
состояния — по slug, заметки — по папке и заголовку. Если запись нашлась и
импорт ничего бы в ней не изменил, она молча пропускается; если данные
разошлись — спрашиваем, что делать (перезаписать, оставить обе, пропустить),
с галочкой «так же поступать с остальными» — своей на каждый раздел.
Карточку каталога «из коробки» перезаписать нельзя (она только для чтения),
поэтому для неё предлагаются только «оставить обе» и «пропустить». Файлы из
архива тоже переносятся один раз: повторный импорт узнаёт их и оставляет
прежние ссылки.

Импорт доступен только ДМ и, разумеется, не даёт прав на чужой платный
контент: переносится ровно то, что уже есть у вас.

## Экспорт и импорт мира

На экране миров (`/worlds.html`) у каждого мира есть кнопка **⬇** — она
скачивает мир одним файлом `*.beacon-world.zip`: сцены, журнал,
пользовательские библиотеки (бестиарий/заклинания/предметы/справочник/
состояния), плейлисты, «готовые персонажи» и все загрузки (карты, токены,
аудио).

В диалоге экспорта есть галочка **«Перенести аккаунты (игроков и ДМ) с
персонажами»** — с ней в архив едут аккаунты (игроки этого мира и все ДМ, с
хешами паролей), их листы и инвентарь, а токены на картах и раздача прав в
журнале остаются привязанными к владельцам.Логин, уже занятый на целевом сервере, получает суффикс `(2)`.
Импортированные аккаунты ДМ становятся глобальными — как основной `dm`.

Кнопка **«Импортировать мир из .zip»** там же создаёт из такого архива
новый мир (существующие миры не трогаются) — запустить его нужно вручную.
Ссылки на загрузки при импорте автоматически переписываются под новый мир.

Пригодится для резервной копии, переноса между серверами и обмена готовыми
приключениями.

## Несколько ДМ

В панели **«Аккаунты»** на столе ДМ можно завести ещё один аккаунт с ролью
«ДМ». Такой аккаунт глобален (как основной `dm`): видит все миры и обладает
полными правами ДМ в любом запущенном. Несколько ДМ могут одновременно
находиться в одном мире — правки не конфликтуют и не блокируются
(последнее нажатие побеждает). Второй ДМ заходит в уже запущенный мир
кнопкой «Открыть стол →»; жать «Запустить» на другом мире, пока первый ДМ
играет, не стоит — это переключит активный мир для всех. Последний аккаунт
ДМ удалить нельзя.

## English summary

**Beacon Table** is a self-hosted, open-source virtual tabletop (VTT) for
D&D 5e and other TTRPGs, written in Go — ships as a single binary, no
mandatory cloud service, no subscription.

It runs in a hybrid mode: the DM runs the scene from a tablet, a TV/projector
in the room mirrors it live over the LAN with zero login, while remote
players can join the same room over the internet with an account.

Highlights: WebGL scene renderer (PixiJS), dynamic lighting & fog of war,
line-of-sight from tokens, video map backgrounds and animated tokens,
character sheets & accounts, DM bestiary/spellbook, status conditions with a
Foundry-style token palette that actually apply their numeric effects (AC,
speed, ability scores, per-turn HP), ambient audio + DM playlists, wiki-style
DM notes.

The out-of-the-box content catalog ships **SRD 5.1/5.2 content only**
(CC-BY-4.0/OGL) — no proprietary Wizards of the Coast book content is
redistributed; DMs add their own homebrew/imported content locally.

📖 Full docs are primarily in Russian (the project's primary community is
Russian-speaking)
Contributions and issues in English are welcome.

**Quick start:** grab a prebuilt binary for your OS from
[Releases](https://github.com/major1ink/Beacon-Table/releases/latest) and
run it — no Go toolchain needed, frontend and SRD data are embedded. To
build from source: `git clone https://github.com/major1ink/Beacon-Table.git && cd Beacon-Table && go run ./cmd/beacon-table`

Licensed under AGPL-3.0. Bundled default content catalog is SRD 5.1/5.2 only
(CC-BY-4.0/OGL) — no proprietary WotC book content is redistributed.
